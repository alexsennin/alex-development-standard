# Informe de aprobación v1.3.2

Fecha: 2026-10-06. Estado: **vigente y de adopción obligatoria**. v1.3.1 queda histórica.

## Motivo
La v1.3.1 definía capability routing pero podía inducir a creer que Codex Desktop cambiaba modelos automáticamente. v1.3.2 separa contrato y runtime: **AXIOM ejecuta routing automático; Codex Desktop es compatibilidad manual**.

## Cambios
- AXIOM se formaliza como runtime oficial de referencia.
- AXIOM coordina Codex CLI; no es un modelo.
- ROUTER barato queda aislado y sin escritura.
- En AXIOM, selección de modelos/reasoning es automática.
- En Codex Desktop, el inicio seguro es FOCUSED/Luna Alto y los cambios siguen siendo manuales.
- Perfil económico predeterminado: Codex CLI autenticado con ChatGPT, sin API key.
- Implementación inicial de AXIOM debe ser secuencial y conservadora; RELEASE automático queda fuera hasta validar routing/ejecución en trabajo real.

## Proyectos reales
Mundo de Colores, Docencia y Fema continúan como proyectos reales iniciales de adopción/validación.
